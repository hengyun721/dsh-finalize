一个 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 插件：**文件交付的那一刻跑一次检查，别的地方都不出现**。它清掉文档库留下的生成器指纹、重算真正能算准的统计字段，并把**不能靠编造解决**的东西收进侧边面板，而不是写进文件里。

> **设计原则：只修可以证明是错的东西，绝不伪造证据。**
> 编辑时长、修订历史、批注、"本文由人撰写"这类声明，一律只报告、不写入。`Application` 字段是**删掉**，不是改成假的 `Microsoft Office Word 16.0`——缺失很平常，撒谎会和包里其它字段自相矛盾。

## 为什么做这个

`python-docx`、`python-pptx`、`openpyxl`、LibreOffice 生成的文件自带"出生证明"：作者字段写着库名、创建时间是 2013 年的模板日期、四十页的报告 `Words=0`、还留着一张模板缩略图。这些是 bug，不是风格，任何人解压就能看见。

而常见的建议——伪造编辑时长、编一个修订次数——只会更糟：它和你改不动的字段（`rsid` 痕迹、真实保存历史）直接冲突，一查就穿。这个插件只做诚实的那一半：把错的改对，把只有人才能提供的收进面板。

## 它做什么

| 格式 | 自动修 | 只报告，不代填 |
|---|---|---|
| `docx` | 作者与描述、模板日期、`Application`/`AppVersion`、字数/字符数/段落数/行数、模板缩略图 | `TotalTime=0`、页数、标点、未解决批注、未接受修订、隐藏文字与白色文字 |
| `pptx` | 同套 core 属性、幻灯片/备注/隐藏页统计、字数 | 没有演讲者备注、裁剪图片的原图仍在 `ppt/media`、隐藏幻灯片与隐藏对象、批注、演讲者备注 |
| `xlsx` | core 属性、`TitlesOfParts` 与实际 sheet 名对齐 | 全表 0 条公式、透视缓存残留已删除的数据、外部链接、隐藏工作表/行/列、批注 |
| `odt` `ods` `odp` | `meta:generator`、作者、日期、`meta:document-statistic`、缩略图及其 manifest 条目 | `meta:editing-duration=PT0S`、只保存过一次、批注、隐藏文字与隐藏工作表 |
| `pdf` | **什么都不改——只读** | Producer/Creator/XMP、增量更新、缺少书签、数字签名、可提取文本里的标点 |

一次交付多个文件，会逐个独立处理；同一会话里多次交付，30 分钟内合并成一份报告，而不是互相覆盖。

## 文本检查

交付文档时，正文段落还会做一次标点检查：判断每一段属于哪种语言，再找出不属于它的标点。语言按字符类型（汉字 / 假名 / 谚文 / 拉丁字母）逐段判定，拉丁段落再用变音符号和停用词区分英、法、德。

| 语言 | 应该用 | 会被标记的例子 |
|---|---|---|
| 中文 | `，。！？；：、（）“”` | `这是测试,包含逗号` |
| 日文 | `、。「」『』` | `テスト，です` |
| 韩文 | 半角 `, . ? !` | `테스트，입니다` |
| 英/法/德 | 半角，加上各自语言的引号（`« »`、`„ “`） | `sentence，with` |

另外还会查：标点前的多余空格、三个以上连续重复的标点、不成对的 `“ ”` / `「 」` / `『 』`。

**只报不改**——盲替换标点误伤代码、URL、公式和引用的概率远高于收益。面板里每组问题都可以展开成逐条记录（最多 50 条，含原文片段和建议写法）。检查会跳过 URL、邮箱、路径、小数和列表编号（`1.`、`3.2`）；表格单元格只检查长度超过 8 个字符的内容。

PDF 会尝试解码文本层：Flate 压缩的内容流、`Tj`/`TJ` 操作符，以及每个字体的 `ToUnicode` 映射（含 Identity-H CID 字体），所以 Word / LibreOffice 导出的 PDF 能覆盖。扫描件、没有 `ToUnicode` 的字体、把文字转成轮廓的页面读不出来——这类文件会明确标注「未检查」，而不是猜。

**只判断你自己写的内容。** 交付的文档如果复用了用户提供的文档里的段落，这些段落视为模板：不会被列为待修问题，而且它们的标点风格会成为新内容的基准——模板写「一:」，接着写「二:」就是符合模板，不算错误。用户自己改过的段落同理：只提示，不改。

检测是自动的：同目录里修改时间更早、且至少四分之一段落（最少 3 段）与交付文件重合的最新 Office 文件，会被当作基线。`textCheck.templates` 可指定固定路径，`textCheck.baseline: false` 关闭自动检测。

## 审阅状态

文件带出门的东西不止看得见的那些。交付前会报告还挂在文件上的：

| 检查项 | 内容 |
|---|---|
| 未解决批注 | 条数、作者、日期、每条的内容（docx、pptx、xlsx、odf） |
| 未接受修订 | 处数、作者，以及被删除的文字（docx） |
| 隐藏内容 | 隐藏文字、白色文字、隐藏幻灯片与隐藏对象、演讲者备注、隐藏工作表、隐藏行与列 |

每项都按文件列出，面板里可展开看逐条明细。**不会自动删除或接受**——某条批注是内部讨论还是有意保留，得你决定。干净的文件只显示一行：`审阅状态：无批注、无修订、无隐藏内容`。

## 安装

这是一个 DSH bundle：带 `dsh.bundle.patch` 的普通包，没有构建步骤，也没有运行时依赖。

```bash
git clone https://github.com/hengyun721/dsh-finalize.git
dsh plugin --profile desktop add /绝对路径/dsh-finalize
```

也可以在 Harness 内用插件管理器安装该目录（`install_bundle`，target 指向上面的绝对路径）。如果提示 `restart-required`，重启一次。

## 使用

不需要调用任何东西。用 `present`（或已配置的传输）交付文件，检查在工具**真正执行之前**跑完，文件落盘时已经是处理过的。文本检查只针对交付的文档，普通回答不会被扫描。

相对路径按**会话工作目录**解析，不是 Host 进程目录。读不到的文件会作为「处理失败」进面板、计入角标，并同时显示原始路径与解析后的路径——不会再无声无息消失。

消息操作栏里会出现一个盾牌图标，和复制 / 赞 / 踩 / 分支并排：

| 状态 | 含义 |
|---|---|
| 灰色 | 本会话还没有交付记录 |
| 琥珀色带数字 | 有这么多项需要人工处理 |
| 点击 | 打开面板，按文件列出「已修 / 待人工 / 只读」 |

面板里还有一个**扫描最近文件**：不用交付，直接对工作区里最新的 Office 文件跑一遍。文档是脚本生成、没走 `present` 的时候用这个。

## 配置

```yaml
- id: dsh-finalize
  name: 'dsh-finalize'
  config:
    author: ''
    triggerTools: [present, qqbot_send_file]
    formats: [docx, pptx, xlsx, pdf, odt, ods, odp]
    scanLimit: 5
    autoFix:
      stripGeneratorFields: true
      dropApplicationField: true
      recomputeStats: true
    textCheck:
      punctuation: true
      languages: [zh, ja, en, fr, ko, de]
      templates: []
      baseline: true
    report:
      surface: panel
```

| 配置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `author` | string | `''` | 写入 `dc:creator`、`lastModifiedBy`、`meta:initial-creator`。留空表示只清除库名，不编造人名。 |
| `triggerTools` | string[] | `present`、`qqbot_send_file` | 触发检查的交付工具。 |
| `formats` | string[] | 全部七种 | 适配器白名单，其余格式标记为 `skipped`。 |
| `scanLimit` | number | `5` | 「扫描最近文件」一次处理多少个文件。 |
| `autoFix.stripGeneratorFields` | boolean | `true` | 移除库名和 `generated by …` 描述。 |
| `autoFix.dropApplicationField` | boolean | `true` | 删除 `Application`/`AppVersion`，而不是伪造 Office 版本号。 |
| `autoFix.recomputeStats` | boolean | `true` | 按正文重算字数、字符数、段落数。 |
| `textCheck.punctuation` | boolean | `true` | 是否对正文做标点检查。 |
| `textCheck.languages` | string[] | 全部六种 | 允许被检查的语言：`zh`、`ja`、`ko`、`en`、`fr`、`de`。 |
| `textCheck.templates` | string[] | `[]` | 显式指定模板路径（相对交付文件所在目录）。 |
| `textCheck.baseline` | boolean | `true` | 未指定模板时，按段落重合度自动识别基线。 |
| `report.surface` | `panel` \| `silent` | `panel` | 是否渲染操作栏按钮。 |

### 引擎结构

`lib/office.js` 刻意保持单文件、扁平 API：

| 符号 | 作用 |
|---|---|
| `readZip(buffer)` | 解析中央目录，得到 `{ name, data, time, date }`。不支持 ZIP64。 |
| `writeZip(entries)` | 用 `deflateRaw` 重新打包。名为 `mimetype` 的条目保持不压缩且位置不变——ODF 的硬性要求。 |
| `finalizeDocx` / `finalizePptx` / `finalizeXlsx` | OOXML 适配器，共用 `fixCore`、`stripApplication`、`dropThumbnail`、`commonUnresolved`。 |
| `finalizeOdf` | 基于 `meta.xml` 与 `META-INF/manifest.xml` 的 ODF 适配器。 |
| `inspectPdf` | 正则级 PDF 检查器，只返回观察结果，绝不改写字节。 |
| `finalizeOffice(bytes, kind, options)` | Host 半边调用的分发入口。 |

## 兼容性

设计上就是为了和别的插件共存，不改变它们的行为。

- **不注册工具、不写提示词**：模型的工具列表和系统提示词都不变，token 计算和工具选择不受影响。
- **只有一个被动监听器**：`tools/pre-execute` 只在配置的交付工具上触发，永远 `return next()`，自身异常被吞掉，既挡不住也改不了别的工具调用。
- **不绑定传输层**：钩的是交付工具，不是 QQ / Web / CLI 通道，换传输照常工作。
- **命名空间独立**：路由是 `/api/finalize.report` 和 `/api/finalize.scan`，slot id 是 `dsh-finalize`，与官方的 `deliverables`、`changes.*`、`presented` 都不冲突。
- **调试默认关闭**：不开 `DSH_FINALIZE_DEBUG=1` 时，除被交付的文件外不写任何文件。

## 已知限制

- 页数需要排版引擎，插件只报不猜。
- ODF 只改 `meta.xml` 和 manifest 里的缩略图条目，其它不动；结构已验证，但 CI 不覆盖"用 LibreOffice 实际打开"。
- 旧二进制格式（`doc`、`xls`、`ppt`）、`rtf`、`ipynb` 未实现。其中 `doc` 在 `PIDSI_EDITTIME` 里存的是**真实**累计编辑时长，值得优先补上。
- 这不是作者身份检测工具，也不声称文件"看起来像人写的"。它只做两件事：去噪、报矛盾。

## 调试

启动 Harness 前设置 `DSH_FINALIZE_DEBUG=1`，会在系统临时目录写入 `dsh-finalize.log` 和 `dsh-finalize-last.json`。默认关闭，不会往工作区写东西。

除此之外不落任何文件：文档字节读进内存、原地写回，没有临时副本、没有 sidecar、没有缓存。Windows 上调试文件位于 `%TEMP%`（`C:\Users\<用户名>\AppData\Local\Temp`），macOS / Linux 上是 `$TMPDIR` 和 `/tmp`。
